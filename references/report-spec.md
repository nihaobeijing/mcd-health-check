# 体检口径与评分标准

本文件定义体检引擎的全部计算口径，任何报告数字都可以按此复算。

脚本位置：`scripts/health_report.py`。所有参考值集中在文件顶部常量区。

---

## 1. 参考值来源

| 常量 | 值 | 来源 |
| --- | --- | --- |
| `REF_DAILY_KCAL` | 2000 kcal | 中国居民膳食指南（2022），轻体力活动水平每日能量需要量的中位取值 |
| `REF_MEAL_KCAL` | 700 kcal | 单餐热量上限，取每日推荐的三分之一再留余量 |
| `REF_DAILY_SODIUM_MG` | 2000 mg | WHO 每日钠摄入建议上限 |
| `REF_DAILY_PROTEIN_G` | 60 g | 每日蛋白质参考摄入 |
| `REF_DAILY_FAT_G` | 60 g | 每日脂肪参考摄入 |
| `REF_DAILY_CARB_G` | 300 g | 每日碳水参考摄入 |
| `REF_FAT_ENERGY_RATIO` | 30% | 脂肪供能比上限（中国居民膳食指南建议 20%~30%） |
| `REF_PROTEIN_ENERGY_RATIO` | 10% | 蛋白供能比下限 |
| `REF_MONTHLY_BUDGET` | 200 元 | 月均消费理性基准（可按个人情况调整） |
| `REF_IMPULSE_ORDER` | 100 元 | 单笔超过此金额视为冲动大额 |

蛋白质 / 脂肪 / 碳水供能比按 4 / 9 / 4 kcal/g 折算。

---

## 2. 营养匹配

对每个餐品条目按顺序尝试四级匹配，命中即停：

| 级别 | 判定 | 标注 |
| --- | --- | --- |
| 精确 | 归一化后名称与营养表条目相同 | 无标记，精确值 |
| 近似 | 一方名称是另一方的子串，且覆盖率 ≥ 50% | 「按同类单品估算」 |
| 估算 | 落入某个品类且该品类在营养表中有条目 | 复购榜标 `≈` |
| 未覆盖 | 以上都不成立 | 不参与热量推断，报告底部列出 |

- **归一化**：去空格、全角括号转半角、去掉「的」字。
- **酱料**：名称含「酱」的条目按 0 热量、0 钠计入（调味酱）。
- **品类**判定按关键词优先级：`condiment → drink → dessert → side → chicken → breakfast → burger`，都不命中为 `other`。
- 品类估算取该品类在营养表内各项的**中位数**。

### 覆盖率口径

```
known_ratio = (精确命中 + 近似命中 + 酱料) / 全部餐品条目数
```

估算项计入分母但不计入分子——报告里的「覆盖率」因此是**保守**口径。

### 单餐口径

热量按**订单**汇总，不是按餐品条目：

```
单餐平均热量 = 有效订单总热量 / 有效订单数
单餐平均钠   = 有效订单总钠 / 有效订单数
```

订单内先展开 `comboItemList`（套餐子项），子项没有子项时用商品本身。

## 3. 四维评分

每个维度从 100 分起扣，最低 0 分。总分为加权平均：

```
总分 = 营养均衡 × 0.30 + 钱包健康 × 0.20 + 权益把控 × 0.25 + 习惯结构 × 0.25
```

评级：S ≥ 90，A ≥ 80，B ≥ 70，C ≥ 60，D < 60。

### 营养均衡（权重 30%）

| 条件 | 扣分 |
| --- | --- |
| 单餐平均热量 > 700 kcal | `min(35, (超出差值) / 15)` |
| 单餐平均钠 > 700 mg（每日上限的 35%） | `min(25, (超出差值) / 12)` |
| 脂肪供能比 > 30% | `min(20, (超出差值) × 150)` |
| 蛋白供能比 < 10% | `min(15, (差值) × 200)` |
| 饮料热量占比 > 35% | `min(15, (超出差值) × 120)` |

### 钱包健康（权重 20%）

| 条件 | 扣分 |
| --- | --- |
| 取消订单占比 > 10% | `min(30, (超出差值) × 200)` |
| 月均消费 > 200 元 | `min(25, (超出差值) / 8)` |
| 存在单笔 > 100 元的订单 | `min(20, 笔数 × 8)` |
| 客单价 > 50 元 | `min(15, (超出差值) × 0.8)` |

### 权益把控（权重 25%）

| 条件 | 扣分 |
| --- | --- |
| 过期积分占比 > 20% | `min(35, (超出差值) × 110)` |
| 有 3 天内到期的券 | `min(18, 张数 × 6)` |
| 本月有即将过期积分 | `min(15, 积分 / 4)` |
| 可用积分 / 累计积分 < 40% | `min(10, 差值 × 40)` |

过期积分占比 = `expiredPoint / accumulativePoint`。

### 习惯结构（权重 25%）

| 条件 | 扣分 |
| --- | --- |
| 单一品类热量占比 > 60% | `min(25, (超出差值) × 90)` |
| 深夜档订单占比 > 30%（22:00–05:00） | `min(20, (超出差值) × 100)` |
| 单均点过的不同餐品数 < 1.2 | `min(20, 差值 × 25)` |
| 活跃天数 < 订单数 × 0.7 | 10 |

## 5. 建议生成

建议是规则触发的，每条都绑定一个具体指标，不做泛泛而谈。按 `urgent → warning → info` 排序。

| 级别 | 触发条件 | 建议内容 |
| --- | --- | --- |
| 速办 | 券在 3 天内到期 | 点名券名与剩余天数 |
| 速办 | 本月有即将过期积分 | 去麦麦商城换实物 |
| 注意 | 过期积分占比 > 20% | 点明过期比例 |
| 注意 | 单餐钠 > 每日上限 35% | 给出具体替换建议 |
| 注意 | 饮料热量占比 > 35% | 换无糖/玉米杯 |
| 建议 | 深夜档占比 > 30% | 最后一单换小食 |
| 建议 | 有取消订单 | 点名取消金额与占比 |
| 建议 | 活动日历有活动 | 点名活动标题 |
| 建议 | 有抽奖活动 | 折算可用积分可抽次数 |

---

## 6. 边界约定

- **已取消订单**不计入消费、热量与门店统计，但计入「取消订单」提醒。
- **未覆盖餐品**不参与任何热量推断，只在覆盖率说明里列名。
- **积分**：以 `query-my-account` 的五个字段为准，不做推算。
- **券的到期时间**从返回 markdown 里正则解析，以 `now-time-info` 的服务器日期为基准计算剩余天数。
- 报告不给出医疗诊断、处方或具体减肥方案，只做数据层面的对比与可执行替换建议。
